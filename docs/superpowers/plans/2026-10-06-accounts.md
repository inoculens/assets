# Accounts (approach A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Organize the portfolio into ticker-bound accounts with per-card P&L, account-scoped trades, and a default account.

**Architecture:** Store gains `accounts[]` + `trade.accountId` + `settings.defaultAccountId` under a new `inoculens.v2` key; Ledger engine untouched (runs on per-account filtered trades); Ui renders stacked account cards, an account-select trade dialog with locked symbol, and grand totals. Tolerant v1 file import groups legacy trades into per-symbol accounts.

**Tech Stack:** Vanilla HTML/CSS/JS (ES2020), localStorage, no dependencies. Paths below are repo-root-relative (repo root is the `assets/` directory itself).

**Spec:** `docs/superpowers/specs/2026-10-06-accounts-design.md`

## Global Constraints

- No backend, no keys, no analytics, no cookies.
- No build step; works from `file://` and any static host.
- `localStorage` key for the new shape is exactly `inoculens.v2` (old `inoculens.v1` data is never read or migrated at runtime).
- Export envelope is exactly `{app:"inoculens-assets", version:2, exportedAt, settings, accounts, trades}`.
- Failed import rejects entirely, existing data untouched.
- Ledger engine math (`computeAverage/computeFifo/computePositions`) is not modified; per-account P&L filters trades first.
- Unknown live price stays `null` (never 0) through all new code.
- Trade-dialog and settings-dialog element IDs used by `tests.html` are preserved unless the task says to update the harness in the same commit.

## Review Focus

- Trade referencing an unknown `accountId` (hand-edited file) → expect full import reject, existing data untouched.
- Deleting the default account → expect default falls back to first remaining account, Add-trade keeps working.
- v1 file (account-less trades, mixed symbols) → expect one auto account per symbol with P&L identical to pre-accounts math.
- Two accounts sharing one ticker with different trades → expect fully separated P&L, no cross-contamination.
- Zero accounts with zero trades (fresh state) → expect empty-state prompt only, no crash, Add-trade shows a hint.

### Task 1: Store v2 (accounts + accountId + default)

**Files:**
- Modify: `app.js` (Store section only)
- Modify: `tests.html` (Store + new Accounts-storage tests)

**Interfaces:**
- Consumes: existing `normalizeTrade`, `isValidImportTrade` (extended, not replaced).
- Produces:
  - `Account = {id:string, name:string, ticker:string, createdAt:string}`
  - `defaultState() -> State` where `State = {settings:{mainCurrency:string, costMethod:'average'|'fifo', defaultAccountId:string|null}, accounts:Account[], trades:Trade[], priceOverrides:Record<string,number>}` and `Trade` gains required `accountId:string`
  - `loadState() -> State` (reads `inoculens.v2`; corrupt/missing → `defaultState()`)
  - `saveState(s:State) -> void` (throws `Error('storage-unavailable')` on failure, unchanged contract)
  - `exportState(s:State) -> string` (envelope exactly `{app:"inoculens-assets", version:2, exportedAt, settings, accounts, trades}`)
  - `importState(json:string) -> State` (accepts version 2 as-is; accepts version 1 by grouping its trades into per-symbol accounts `{id:uid-ish, name:symbol, ticker:symbol}` and setting default to the first; throws on anything else, atomically)
  - `accountById(st:State, id:string) -> Account|null`
  - `defaultAccount(st:State) -> Account|null` (settings.defaultAccountId if it exists, else first account, else null)
